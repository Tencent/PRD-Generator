# Contributing

Thank you for your interest in PRD Generator. Issues and pull requests are welcome. (中文版见下方。)

## Filing an issue

Before filing, please make sure that:

- it is a bug or a feature suggestion;
- you have searched the existing issues and it is not a duplicate.

For bug reports please include: your operating system and Python version, the AI tool you use, the command you typed, the output of `python3 scripts/prdkit.py doctor`, and the related error message or screenshot. **Never paste tokens, keys or unreleased business content into an issue.**

Do not report security problems in a public issue; see [SECURITY.md](SECURITY.md).

## Submitting a pull request

1. Fork the repository and branch from `main`.
2. After your change, run the regression tests from the repository root; all of them must pass:

   ```bash
   python3 tests/regress.py
   ```

3. Write commit messages that say what changed and why. Keep one pull request to one topic so it is easy to review.
4. Open the pull request and describe the scope of the change and how you verified it.

### Conventions

- **Do not hand-write what a command can generate**: screenshots, flow diagrams, page lists, flow lines, prototype links and Appendix B are all generated by `prdkit` commands. Change the generating logic, not the output.
- **If you change `lint.py` / `flow.py` / `shot.py` / `style.py` or the template styles, run the regression.** A new rule needs a matching regression assertion.
- **The core must not depend on any hosting service or credential.** Anything that talks to an external service is written as an optional publisher under `scripts/publishers/`; see `references/publish.md` §3.
- **Credentials are read only from environment variables**, never printed or written into the spec, logs or any file; a publisher that makes content public must ask the user for explicit confirmation.
- **Do not commit**: personal paths and accounts, tokens or keys, unreleased business data, build caches (`__pycache__/`). The regression has a "release package hygiene" check that blocks these.
- **Language support**: the Chinese output (`zh`, the default) must not change. Any user-visible text you add needs both a Chinese and an English version (see `scripts/lib/i18n.py`); the Chinese golden baseline in `tests/golden/zh/` must still match.
- Keep Python code compatible with Python 3.8+; the core depends only on the standard library and Playwright.
- New `.py` files must carry the same copyright header as the existing ones.

# 贡献指南

感谢你关注 PRD Generator。我们欢迎 Issue 反馈和 Pull Request。

## 提交 Issue

提交前请先确认：

- 这是一个 bug 或一个功能建议；
- 已在已有 Issue 中搜索过，没有重复。

Bug 报告请尽量带上：操作系统与 Python 版本、使用的 AI 工具、你输入的指令、`python3 scripts/prdkit.py doctor` 的输出，以及相关的报错信息或截图。**不要在 Issue 里贴任何令牌、密钥或未公开的业务内容。**

安全问题请不要公开提 Issue，见 [SECURITY.md](SECURITY.md)。

## 提交 Pull Request

1. Fork 本仓库，并从 `main` 拉出你的分支。
2. 修改后，在仓库根目录运行回归测试，必须全部通过：

   ```bash
   python3 tests/regress.py
   ```

3. 提交信息写清楚“改了什么、为什么”。一个 PR 只做一件事，方便评审。
4. 发起 PR，并在描述里说明改动范围与验证方式。

### 开发约定

- **能由命令生成的内容，不手写**：截图、流程图、页面清单、流转行、关联原型、附录 B 等一律由 `prdkit` 命令生成；改它们的生成逻辑，而不是改产物。
- **改了 `lint.py` / `flow.py` / `shot.py` / `style.py` / 模板样式，必须跑一遍回归。** 新增规则要补对应的回归断言。
- **核心不引入任何托管服务或凭证依赖。** 需要对接外部服务的能力，写成 `scripts/publishers/` 下的可选发布器，约定见 `references/publish.md` §3。
- **凭证只从环境变量读取**，不打印、不写入 spec、日志或任何文件；涉及公开内容的发布器必须要求用户显式确认。
- **不要提交**：个人路径与账号、令牌/密钥、未公开的业务数据、构建缓存（`__pycache__/`）。回归测试里有“发布包卫生”检查，会拦截这类内容。
- Python 代码保持兼容 Python 3.8+，核心只依赖标准库与 Playwright。
- 新增 `.py` 文件请带上与现有文件一致的版权头。
