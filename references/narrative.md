# PRD 叙事规范（让读者读得懂，而不只是“字段齐全”）

PRD 的读者是评审者和开发者。他们看的不是“有没有这个章节”，而是**能不能顺着读下来明白产品怎么用**。本规范是写作时的结构要求，其中可机器判断的部分由 `prdkit.py lint` 检查（L-4xx / L-3xx）。

## 1. 章节按用户旅程排，不按“模块”排

- 3.x 章的顺序 = 用户使用顺序（找到 → 申请 → 归还 → 评价），章名写**用户在这一章完成什么任务**，不写“XX 模块”。
- 章序、章号、章名以 `spec/screens.json` 的 `chapters` 为准，PRD 必须一致（lint L-320 / L-420）。
- 3.0 只做两件事：用 2-4 句话说明“怎么读本文档”；放整体页面流程图（主干页面）。

## 2. 每章固定开头：总览 → 图 → 清单

```
### 3.x {章名}
**本章页面关系总览**：{2-3 句：从哪来、做什么、去哪；点出 1-2 个关键分支}
![3.x 页面关系总览](images/flow-3-x.png)
**本章页面清单**：{表，由 prdkit flow --table 生成}
```

- 总览文字**先于**图，让读者带着结论看图。
- 页面清单表**必须由命令生成**再粘贴，不手写——它和流程图同源，改了页面只需重新生成，避免图文不一致。
- 本章页面+弹窗 ≥ 3 个必须有章级流程图和清单（L-321 ~ L-324）；少于 3 个可以省略，直接写逐页说明。

## 3. 每个页面：先说“从哪来到哪去”，再说细节

页面小节标题固定为 `##### 3.x.3.n 页面交互说明 — {页面名}`，第一行必须是：

```
**流转**：{来源页} 点“{动作}” → **本页** → 点“{动作}”到 {目标页}；{异常/边界去向}
```

写作要点：

- 流转行里的页面名必须与页面清单、流程图节点名一致；**流程图里与本页相连的页面都要写到，没连线的页面不能写**（lint L-412 / L-413 机器检查，含返回线和他章页面）。
- 弹窗、页面状态（空态、完成态、已申请态）各自独立小节，各自一张截图，不合并。
- 元素表只写**会影响实现的信息**：显示条件、置灰条件、取值范围；“按钮：点击按钮”这种无信息的行不要写。
- 交互规则用编号列出，每条形如“**触发 → 结果**”，必须包含失败/异常分支。

## 4. 数字和术语

- 一级章号必须连续：省略可选章节（如“5 上线策略”）后，后面的章号顺延（L-206）。
- 业务规则编号全局唯一（BR-01…），正文引用规则时写编号（“见 BR-03”），不复制规则原文。
- 数值带单位和边界：“24 小时”“1-3 天”“≤ 50 字”，不写“较短”“适量”。
- 全文同一概念同一名称；术语在附录 A 有定义。
- 不要把内部编号、工单号、人名写进正文。

## 5. 评审修订时

- 在“修订说明”表追加一行：**改了什么、为什么**，不写“优化文案”这类空话。
- 新增或改动的页面，同步更新 spec → 重新截图 → 重新生成流程图和清单 → 再改正文（详见 `revision.md`）。

## 6. 禁止项

- 禁止文本线框图 / ASCII 画 UI（L-104）。页面展示只能用 `shot` 生成的截图。
- 禁止手画 Mermaid 页面流程图当作 3.x 流程图；业务流程（2.2）才用 Mermaid。
- 禁止在 PRD 中出现 localhost 链接（L-501）。
- 禁止标题带【必填】【选填】等模板标注（L-102）。
