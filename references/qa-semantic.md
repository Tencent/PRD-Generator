# 语义质检清单（需要 AI 判断的部分）

机器能判定的规则已经全部移入 `python3 scripts/prdkit.py lint`（得分、错误、提醒直接看命令输出，不要再手工 grep）。本文件只保留**必须读懂内容才能判断**的规则。

流程：先 `lint` 到 0 错误 → 再按本清单逐条判断 → 把问题和修复一起汇报，能自动改的直接改。

## 2. 语义规则（AI 逐条判断）

判断时必须给出**具体位置和理由**，不要只写“通过”。

### 2.1 目标与背景

| ID | 检查项 | 级别 |
|---|---|---|
| M-01 | 核心目标至少 1 个**可量化**指标，且写明统计口径或来源 | warn |
| M-02 | 背景回答了“为什么现在做”，而不是只介绍产品 | warn |
| M-03 | 功能架构至少 2 个一级模块（单页面 H5 / Landing Page 标“已豁免”） | error |

### 2.2 业务逻辑

| ID | 检查项 | 级别 |
|---|---|---|
| M-10 | 用户故事符合 As a / I want / So that，且 So that 是价值而不是复述功能 | warn |
| M-11 | 每条业务规则可执行、无歧义，有边界条件（数值、状态、例外） | warn |
| M-12 | 每个模块的异常处理覆盖：网络异常、数据为空、权限不足、超时/并发冲突中适用的场景 | error |
| M-13 | 数据字段表的“字段 / 类型 / 必填”三列无空值，校验规则可落地 | error |
| M-14 | 涉及状态变化的核心功能有状态流转说明（stateDiagram 或表） | warn |
| M-15 | Mermaid 代码块语法正确、能渲染（参与者/节点命名一致） | error |

### 2.3 页面说明与流转

| ID | 检查项 | 级别 |
|---|---|---|
| M-20 | 每页“流转”行的动作描述是否准确（页面名与流程图是否一致已由 lint L-412 / L-413 检查，这里只看“点哪个按钮、什么条件下去”写得对不对） | error |
| M-21 | 元素表只写影响实现的信息（显示/置灰条件、取值范围），没有“按钮：点击按钮”这类空话 | warn |
| M-22 | 交互规则每条都是“触发 → 结果”，且有失败/异常分支 | warn |
| M-23 | 截图内容与小节描述对得上（例如“空态”小节配的确实是空态截图）——**必须看图** | error |
| M-24 | 章内顺序符合用户使用顺序，章名是“用户任务”而非“XX 模块” | warn |

### 2.4 一致性

| ID | 检查项 | 级别 |
|---|---|---|
| M-30 | 术语全文统一，附录 A 已定义关键术语 | warn |
| M-31 | 版本号、产品名全文一致 | error |
| M-32 | 与知识库已有术语/规则一致（Step 2 检索过才检查） | warn |
| M-33 | 范围描述与原型、截图一致：范围里写“不含 X”，原型就不能出现 X 的入口（Tab、按钮、空态引导文案）；范围里写“包含 X”，原型必须有 X | error |
| M-34 | 每条业务规则、每个原型可见元素，都能在某个页面/状态/弹窗或明确的“后续版本/由后台执行”说明里找到落点；原型里有的入口，PRD 里不能没有说明 | error |

## 3. 评分

- 机器分：由 `lint` 输出（error 扣 5，warn 扣 2，满分 100）。
- 语义分：在机器分基础上，按本清单同样规则扣分（error 5，warn 2）。
- 汇报格式：

```
机器校验：{分}/100（{N} 错误 {M} 提醒）
语义质检：{K} 项问题
  - [M-23 error] 3.1.3.2：小节写“空态”，截图实际是列表有数据 → 已重新截图
  - [M-11 warn] BR-04：“尽快处理”无边界 → 已改为“24 小时内”
综合：{分}/100（≥90 可直接评审；80-89 微调后评审；60-79 需补充；<60 建议重做）
```

## 4. 修复原则

- 能确定的直接改（残留注释、缺失的边界条件取值若用户已定义）。
- 需要 PM 决策的（指标目标值、规则取值）不要编造：能预设的在第 1 步预设并经用户确认，真无法预设的标 `[待确认-需PM补充]` 并进附录 C。
- 修复后重新运行 `lint`，确认没有引入新问题。
