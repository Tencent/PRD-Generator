# 质量闸门协议

目标：**用户看到的永远是已经自检并修过一轮的版本**。质检只是兜底，首先靠脚本生成（流转行、页面清单、章号、样式）让错误无从产生。

## 1. 闸门一览

| 闸门 | 命令 | 什么时候跑 | 检查什么 |
|---|---|---|---|
| `env` | `prdkit.py check env` | 开始前 | Python、Chromium、**中文字体**（缺字体会让截图和流程图出现方块乱码） |
| `map` | `prdkit.py check map` | **页面登记完成后、给用户看业务流程之前** | spec 校验（草案模式）、草案流程图自检、边标签规则（FLOW-025/026） |
| `style` | `prdkit.py check style` | 风格与配色给用户确认之前 | 风格是否已确认、主色是否已确认、配色依据是否记录 |
| `prototype` | `prdkit.py check prototype` | 原型给用户评审之前 | spec 与原型文件对应、截图成功、页面脚本无报错、无写死色值、无外链、引用了样式、**原型里的页面跳转与流转一致（PROTO-020/021/022）** |
| `flow` | `prdkit.py check flow` | 流程图给用户评审之前 | FLOWGEO 几何自检（穿节点、贴边、标签压线等） |
| `prd` | `prdkit.py check prd` | PRD 成稿、交付之前 | lint（格式、结构、图文一致、流转行一致、可交付） |

`prdkit.py check all` 按上面顺序逐关检查，遇到未通过的就停。

## 2. 发现问题怎么处理

每条问题都带分级和修法：

| 分级 | 含义 | 处理 |
|---|---|---|
| 可直接修复 | 机械、结果唯一（残留注释、章号顺延、流转行与图不一致、缺样式引用等） | 直接改，改完重跑同一条命令 |
| 需要判断后修改 | 能自行判断，但结果不唯一（标签措辞、写死色值换成哪个变量、连线怎么走） | 改完重跑；最终汇报里说明改了什么 |
| 需要用户决策 | 业务取值、主色、范围取舍等 | **不要编造**。能预设的在第 1 步（需求理解）里预设并让用户确认；真无法预设的才进“待补充”（附录 C） |

## 3. 循环与止损

```
跑闸门 → 有错误？ → 按分级修 → 重跑 → …
```

- 最多 3 轮。
- **止损**：同一条错误连续 2 次检查仍未消失，命令会退出码 3 并打印“⛔ 止损”。此时不要再用同样的办法重试，退一层重新分析根因（换修法？问题其实在上游文件？），再继续。仍不行就如实告诉用户。
- 只有 0 错误才能进入“交给用户确认”。提醒（warn）可以带着交付，但要在汇报里说明。

## 4. 交给用户时怎么说

自检结果**默认折叠**：交付消息里只在有重要修正、或有需要用户决策的事项时用一行带过；用户说“看质量明细”再展开：

```
自检：发现 {N} 项 → 已自动修正 {M} 项 → 待你确认 {K} 项
  已修正：{一句话列出，如“流转行与流程图不一致 ×2、章号顺延”}
  待补充：{真无法预设的事项，明细在 PRD 附录 C}
```

`PEND-001` 提醒对应的就是“待补充”：交付时只告诉用户条数，不逐条念。

## 5. 预防优先

闸门只是兜底。能由脚本生成的内容不要手写：

| 内容 | 生成方式 |
|---|---|
| 页面清单表 | `prdkit.py flow --table` |
| 各页面“流转”行 | `prdkit.py flow --transit`（草稿与 lint 的图文一致口径相同，可直接贴；允许润色动作措辞，不要增删页面名） |
| 章号、章序 | 以 `spec/screens.json` 的 `chapters` 为准 |
| 页面截图 | `prdkit.py shot`，不画线框、不手工截图 |
| 样式 | `prdkit.py style apply`，颜色一律 `var(--color-…)` |
| 导航页 | `prdkit.py index` |

## 6. 语义类检查

闸门里的 `prd` 只做机器能判断的部分。需要读懂内容才能判断的，按 `references/qa-semantic.md` 逐条检查，同样先修后交付。
